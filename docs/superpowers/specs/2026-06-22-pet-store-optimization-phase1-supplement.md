> 修正现有设计 §三，补充试用期、离线分层、设备迁移、管理页面

| 全部 10 条触达规则 | ✅ | ✅ | ✅ |
| 触达规则自定义阈值 | ✅ | ✅ | ✅ |
| 基础看板（AI推荐数+回复率+预计挽回） | ✅ | ✅ | ✅ |
| 企业微信内部通知 | ❌ | ✅ | ✅ |
| 内容日历 + 模板（10套） | ❌ | ✅ | ✅ |
| 专业看板（漏斗+健康度+对比） | ❌ | ✅ | ✅ |
| VIP 确认流 | ❌ | ✅ | ✅ |
| 自动触达 | ❌ | 2条 | 全部 10 条 |
| 一键发送至企业微信 | ❌ | ✅ | ✅ |
| 驾驶舱（LTV/流失预警/月报） | ❌ | ❌ | ✅ |
| 自媒体模板（全量 15 套+云更新） | ❌ | ❌ | ✅ |
| 内置图片生成 | ❌ | ❌ | ✅ |
| 看板自定义 + 数据导出 | ❌ | ❌ | ✅ |

**关键变化**：入门版新增触达回复率、全规则覆盖、自定义阈值——解决 Doc 2 提出的"功能阉割感"问题，让入门用户也能体验 AI 核心价值。

### 2.2 新增：14 天全功能试用期

```
App 首次启动
  ├─ 本地无 License Token → 进入激活页
  │   ├─ "输入激活码" → 正常激活流程（现有设计）
  │   └─ "免费试用 14 天" → 生成本地试用 Token
  │       ├─ 14天内：增长版全部功能可用
  │       ├─ 第 10 天起：页面顶部横幅"试用剩余 X 天，喜欢就订阅吧 →"
  │       └─ 第 15 天：功能降级为入门版，首次进入弹窗引导购买
  └─ 已有正式 Token → 正常启动（不受试用逻辑影响）
```

**实现要点**：
- 试用 Token 本地生成（`LicenseStorage` 中新增 `create_trial_token()`），无需 License Server 参与
- 试用期内不执行心跳校验
- 试用 Token 格式：`{"token": "TRIAL-<timestamp>-<random>", "plan_code": "growth", "expires_at": "<now+14d>", "is_trial": true}`
- 同一台机器只能试用一次（根据 machine_id 去重）

### 2.3 离线宽容期（修正为按套餐分层）

| 套餐 | 离线宽容期 | 降级行为 |
|------|-----------|----------|
| 入门版 | 7 天 | 锁定自动触达 + 看板数据刷新，保留客户档案 + 手动话术生成 |
| 专业版 | 15 天 | 同上，保留企业微信内部通知 |
| 增长版 | 30 天 | 同上，保留内容日历 + 月报查看 |

实现：在 `LicenseStorage.is_grace_period_ok()` 中根据 `plan_code` 读取不同阈值。

### 2.4 新增：License 管理页 + 设备迁移

**Web 端 `/license` 页面**（所有套餐可用）：
- 显示当前套餐等级、到期时间、AI 调用次数剩余
- 离线剩余天数（仅断网时显示）
- 一键续费 / 升级按钮（跳转购买平台）
- 激活码变更入口

**设备迁移流程**：
- 旧设备：管理员在 License Server 后台解绑 machine_id
- 新设备：输入原激活码 → Server 识别为已激活码但允许重新绑定 → 签发新 Token → 旧 Token 自动失效
- App 本地数据迁移：通过加密二维码 + 验证码（见 §七 数据安全）

### 2.5 心跳与预警机制

在现有 24h 心跳基础上新增：
- 网络恢复后自动补发心跳（避免单次断网误判）
- 心跳连续失败 3 次 → 本地弹窗"授权验证失败，请检查网络，剩余 X 天宽容期"
- 到期前 7 天：每屏顶部横幅 + 企业微信通知（专业版+）

## 三、客户触达引擎优化

> 修正现有设计 §四，扩展规则、增加可解释性、闭环追踪、精细化免打扰

### 3.1 触达规则库（扩展至 10 条）

| # | 规则 | 触发条件 | 优先级 | 默认发送方式 | 适用套餐 |
|---|------|----------|--------|-------------|----------|
| 1 | 洗护周期到期 | 上次洗护距今 ≥ care_cycle_days | 中 | 自动 | 全部 |
| 2 | 沉睡唤醒 | 客户未到店 ≥ 90 天 | 高 | 自动 | 全部 |
| 3 | 试用装回访 | 首次试用后 T+1 / T+4 / T+7 | 中 | 自动 | 全部 |
| 4 | 疫苗到期提醒 | 距下次疫苗日期 ≤ 7 天 | 高 | 自动 | 全部 |
| 5 | 驱虫到期提醒 | 距上次驱虫 ≥ 30 天 | 中 | 自动 | 全部 |
| 6 | 宠物生日祝福 | 宠物生日当天 / 前 3 天 | 低 | 自动 | 全部 |
| 7 | 节日营销 | 春节/双11/宠物节 前 7 天 | 低 | **人工确认** | 全部 |
| 8 | 用品复购提醒 | 上次购买粮/猫砂 ≥ 消耗周期 | 中 | 自动 | 全部 |
| 9 | 服务后回访 | 洗护/寄养完成后 T+2 | 中 | 自动 | 全部 |
| 10 | 会员升级通知 | 消费累计突破等级阈值 | 低 | **人工确认** | 全部 |

**数据模型扩展**（在现有 `Pet` 和 `OutreachRule` 上）：
- `Pet` 新增字段：`vaccine_next_date`（下次疫苗日期）、`deworming_last_date`（上次驱虫日期）、`birthday`（生日月日）
- `OutreachRule.trigger_condition` JSON 新增字段：`send_mode`（auto/manual_confirm）

### 3.2 每条触达可解释 —— "决策卡片"

VIP 确认页 / 触达日志中，每条消息附带可解释信息：

```yaml
决策卡片结构:
  trigger_rule: "洗护周期到期"
  evidence:
    last_grooming_date: "2026-05-28"
    days_since: 25
    suggested_cycle: 21
  customer_context:
    name: "豆豆妈妈"
    tier: "VIP"
    total_spent: 6200
    visit_count: 12
    recent_response_rate: "100% (3/3)"
  suggestion: "上次做的是精剪造型，建议在话术中提及保持造型效果"
```

前端展示：在确认页每条消息上方以折叠式卡片呈现，默认展开第一行（触发规则 + 依据），点击展开全部。

**目的**（Doc 3 核心诉求）：降低店员信任成本，让每条 AI 推荐都有据可查。

### 3.3 触达-到店归因闭环

在现有 `OutreachLog` 模型上增强：

```python
# OutreachLog 新增字段
response_time: datetime | None       # 客户回复时间
response_content: str | None         # 客户回复内容
appointment_created: bool = False    # 是否产生了预约
appointment_time: datetime | None    # 预约时间
service_within_7d: bool = False      # 触达后 7 天内是否到店消费
linked_service_record_id: int | None # 关联的服务记录 ID
attributed_revenue: float = 0.0      # 归因收入（该次消费金额）
```

闭环追踪流程：
```
触达发送 → 客户回复？（记录 response_time）→ 产生预约？（记录 appointment）→
7天内到店消费？（自动关联 ServiceRecord）→ 复购？（开启新一轮跟踪）
```

新增看板指标：
- **触达回复率** = 有回复的触达数 / 发送总数
- **触达到店转化率** = 7 天内到店数 / 发送总数
- **触达 ROI** = 归因收入 / 订阅费用

### 3.4 精细化免打扰配置

| 配置维度 | 选项 | 存储位置 |
|----------|------|----------|
| 按渠道 | □ 企业微信免扰 / □ 短信免扰 | Customer.do_not_disturb_channels (JSON) |
| 按时段 | 免扰开始/结束时间（如 21:00-09:00） | Store.settings (JSON) |
| 按消息类型 | □ 促销类不发 / □ 服务类必发 | Customer.dnd_message_types (JSON) |
| 临时免打扰 | 起止日期范围 | Customer.dnd_start / Customer.dnd_end |

免打扰检查顺序（在 `outreach/engine.py` 分发前执行）：
1. 全局免打扰标记 → 跳过
2. 当前时间在客户免扰时段内 → 跳过
3. 当前消息类型在客户禁用列表 → 跳过
4. 当前时间在门店全局免扰时段（如节假日） → 推迟到下一窗口

### 3.5 企业微信合规控制

- **频率硬限制**：单客户每日 ≤ 1 条、每月 ≤ 5 条（写入 `outreach/engine.py`，在分发前校验）
- **授权状态校验**：发送前检查 `customer.external_userid` 有效性
- **全局日限额**：入门版 50 条/天、专业版 200 条/天、增长版 500 条/天
- **触达日志完整记录**：每条消息的发送时间、内容、状态、错误信息（满足企微平台核查）
- **敏感词审核**：话术在发送前经过合规过滤器（见 §七 AI 内容合规）

### 4.2 内容生成升级为"一键生成"

```
优化前（5 步）：
  选模板 → 手动输入变量 → AI 生成 → 手动选 → 复制发布

优化后（3 步）：
  选模板 → 系统自动匹配宠物 + AI 预填生成 → 确认/微调 → 加入日历
```

**自动变量提取**：
- 从 `ServiceRecord` 中自动抓取最近洗护记录中的宠物、品种、服务项目
- 从 `Customer` 中提取高消费客户的宠物信息
- 从门店模板使用历史中推荐高转化模板

**实现**：在 `content_engine/generator.py` 中新增 `auto_fill_variables(template_code, store_id, session)` 方法。

### 4.3 内置图片生成（增长版独占）

在内容生成页面集成图片生成能力：

- 接入开源文生图 API（如 Stable Diffusion API 或云端服务）
- 根据文案内容 AI 自动生成图片提示词（可手动编辑）
- 一次生成 3 张供选择
- 支持简单后处理：添加门店 LOGO、文字叠加

图片生成功能仅增长版可用（通过 `LicenseStorage.get_token()["plan_code"] == "growth"` 控制）。

### 4.4 内容效果闭环

- 发布后手动回填互动数据（点赞/评论/分享/咨询数），系统 7 天后提醒
- 自动计算"互动率"和"转化数"，标注高优模板（top 20%）
- 低互动内容（互动率低于同类均值 50%）自动生成优化建议：调整话题标签、增加优惠钩子、更换发布时间

### 4.5 内容日历智能推荐

推荐逻辑：结合门店近期服务记录 + 节日/活动日历 + 历史高互动模板。

## 五、运营看板优化

> 修正现有设计 §六，重构入门版、增加行动建议、明确指标口径、自定义+导出

### 5.1 入门版看板重构 —— 聚焦"AI 增量价值"

```
┌──────────────────────────────────────────────────────────┐
│  📊 今日概览                           2026-06-22 周一     │
├────────────┬────────────┬────────────┬──────────────────┤
│ 🤖 AI 推荐   │ 📋 待处理    │ 🎯 昨日触达  │ 💰 预计挽回       │
│ 待跟进客户   │ 触达任务    │ 到店转化     │ 营业额            │
│    8人      │    6条      │  3/12=25%   │  ¥2,800          │
└────────────┴────────────┴────────────┴──────────────────┘
```

四个指标全部体现"AI 帮你做了什么"：
- **AI 推荐待跟进**：今日规则扫描命中的客户数（而非只是任务计数）
- **待处理触达任务**：今日需手动确认/发送的触达消息数（入门版无自动发送，全部需人工处理）
- **昨日触达到店转化**：触达带来的实际到店（而非只是"发送数"）
- **预计挽回营业额**：沉睡客户历史客单价 × 唤醒概率

### 5.2 看板"行动建议"模块

每个看板层级底部新增"行动建议"区域，从"展示数据"升级到"指导行动"：

```
📌 今日建议行动
  ⚠️ 客户「王阿姨」已 87 天未到店，历史客单价 ¥320 → [一键生成唤醒话术]
  💡 洗护提醒的触达回复率（38%）显著高于复购提醒（22%），建议本周加大洗护类触达
  📅 今日有 1 条内容待发布：「618宠粮优惠」→ [去发布]
  🔄 客户「李先生」累计消费已超 ¥5,000，建议升级为 VIP → [确认升级]
```

### 5.3 指标说明弹窗

每个核心指标旁添加 `ⓘ` 图标，点击展开计算逻辑：

| 指标 | 计算口径 | 数据来源 |
|------|----------|----------|
| 客户 LTV | 近 12 个月消费总额 ÷ 历史到店月数 | ServiceRecord |
| 流失预警 | 近 60 天无消费 + 近 3 次触达无回复 | ServiceRecord + OutreachLog |
| 客户健康度 | 最近到店时间(40%) + 消费频次(30%) + 触达回复率(30%) | ServiceRecord + OutreachLog |
| 触达到店转化率 | 触达后 7 天内到店客户数 / 触达总数 | OutreachLog + ServiceRecord |
| 预计挽回营业额 | Σ(沉睡客户历史客单价 × 行业唤醒概率 15%) | Customer + ServiceRecord |
| 触达 ROI | 触达归因收入总额 / 订阅费用 | OutreachLog + License |

### 5.4 看板自定义 + 数据导出

- **自定义布局**：拖拽调整指标卡片顺序、隐藏/显示指标（增长版）
- **数据导出**：右上角 [导出 Excel] [导出 PDF] 按钮（增长版）
- **月报自动推送**：每月 1 号生成上月报告 Markdown → Jinja2 渲染 → 推送至老板企业微信（增长版）

## 六、用户体验与角色权限

> 新增模块（原设计未覆盖）

### 6.1 工作台首页重构 —— "每日三件事"

## 七、技术与合规优化

> 新增模块（原设计仅覆盖企微频控，未覆盖 AI 审核、可视化配置、异常监控、数据安全、统一服务层）

### 7.1 AI 内容合规审核

在话术生成和内容生成流程中插入审核环节：

```
AI 生成内容 → 合规审核过滤器
  ├─ 通过 → 正常输出
  └─ 拦截 → 标记违规类型 + 自动替换建议
      ├─ 医疗暗示（"治疗""治愈""处方"） → 替换为"护理""调理""推荐"
      ├─ 绝对化用语（"最好""第一""100%"） → 替换为"推荐""受欢迎""高性价比"
      ├─ 平台违禁词（"加微信""免费领取"等企微敏感词） → 高亮提示人工修改
      └─ 价格误导/虚假承诺 → 拦截 + 提示修改
```

**实现方式**：
- 内置敏感词库（`outreach/sensitive_words.json`），包含医疗/违规/平台禁词三类
- 正则 + 关键词匹配，不依赖额外 LLM 调用
- 审核在 `agents/reminder.py` 的 `execute()` 和 `content_engine/generator.py` 的 `generate_variants()` 之后执行
- 支持门店自定义禁用词白名单（存储在 `Store.settings` JSON 中）

### 7.3 异常监控告警

新增系统监控面板（`/admin/monitoring`，仅管理员/老板可见）：

| 监控项 | 正常阈值 | 告警条件 | 告警方式 |
|--------|----------|----------|----------|
| 触达成功率 | ≥ 95% | < 90% 或 > 5 条/小时失败 | 企微通知 |
| License 心跳 | 每 24h 正常 | 连续 3 次失败 | 本地弹窗 + 企微 |

监控数据来源于 `OutreachLog`、`LicenseStorage`、LLM 调用记录等，定时汇总。

### 7.4 数据安全

| 措施 | 说明 | 优先级 |
|------|------|--------|
| 本地数据库加密 | SQLite 文件通过 `pysqlite3` + SQLCipher 扩展实现 AES-256 加密 | P2 |
| 自动本地备份 | 每日凌晨备份至 `~/.aipet/backups/`，保留最近 7 天 | P2 |
| 云端备份（可选） | 客户授权后同步加密备份至云端，用于设备迁移恢复 | P3 |
| 设备迁移 | 通过加密二维码（含备份密码）+ 短信验证码实现数据安全迁移 | P2 |

数据库加密为 Phase 1 结束前的必做项（涉及客户隐私数据）。

### 7.5 统一服务层（技术债务）

```
现有架构（入口分散）：
  CLI ──→ agents ──→ core
  Web ──→ agents ──→ core      ← 逻辑分散，三种入口各自调用
  Scheduler ──→ agents ──→ core

目标架构（入口统一）：
  CLI ─┐
  Web ─┼──→ services/ ──→ core   ← 业务逻辑集中在 services 层
  Scheduler ─┘                      CLI/Web/Scheduler 只做入口适配
```

**执行方式**：不新建抽象层，而是逐步将 `agents/` 和 `core/` 中的业务编排逻辑下沉到 `services/` 层。Phase 1 末逐步重构，非阻塞项。

## 十、错误处理与降级策略补充

| 场景 | 处理方式 |
|------|----------|
| 试用期 Token 冲突 | 正式激活后自动覆盖试用 Token |
| 频控超限 | 自动推迟到下一可用时间窗口，日志记录 skipped |
| AI 内容审核拦截 | 返回标记后的内容 + 违规原因，前端高亮显示 |
| 图片生成 API 失败 | 降级为输出提示词（现有模式），不阻塞内容生成 |
| 触达规则配置错误 | 前端校验 + 后端 schema 校验，无效配置回退到默认值 |
| 企微外部联系人 API 限流 | 指数退避重试（1min/5min/15min），3次后标记失败 |
| 数据库加密迁移 | 首次启用时自动备份明文 → 创建加密库 → 导入数据 → 删除明文 |

## 十一、设计决策记录补充

| 决策 | 选择 | 理由 |
|------|------|------|
| 试用期实现 | 本地 Token，不依赖 License Server | 降低试用门槛，无需网络即可试用 |
| 触达规则扩展幅度 | Phase 1 一次性覆盖 10 条 | 核心价值功能，规则不足直接影响留存 |
| 入门版策略 | 功能全开但用量分级 + 保留高级锁 | 消除"功能阉割感"，让入门用户感知 AI 价值 |
| 图片生成 | 增长版独占，集成开源 API | 作为增长版核心差异化卖点 |
| 首页定位 | 品牌不变，交互改为"每日三件事" | 保留品牌资产，聚焦日常经营核心流程 |
| AI 内容审核 | 本地敏感词库 + 规则引擎 | 不依赖额外 LLM 调用，降低延迟和成本 |
| 角色权限 | 三角色模型（老板/店员/管理员） | 覆盖宠物店实际人员结构 |
| 统一服务层 | Phase 1 末逐步重构 | 技术债务，不阻塞业务功能交付 |
