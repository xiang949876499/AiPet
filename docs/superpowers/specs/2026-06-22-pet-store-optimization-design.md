# 宠店 AI 管家 — 全面优化设计文档

> 基于《宠店 AI 管家产品设计文档 V1.0 MVP 版》的全面升级设计
> 日期：2026-06-22 | 状态：待实施

## 一、需求摘要

在现有 MVP 基础上，围绕四个方向进行全面升级：

| 方向 | 目标 | 用户决策 |
|------|------|----------|
| 商业化闭环 | License 激活码 + 订阅收费 + 续费管控 | 单店部署，第三方发码平台收款，在线激活 |
| 客户触达自动化 | 从手动复制粘贴升级到分层自动推送 | VIP 人工确认，普通客户自动规则 |
| 自媒体能力升级 | 模板化 + AI 填充 + 日历编排 | 模板驱动，AI 辅助填充细节 |
| 运营效果可视化 | 从任务列表升级到分层驾驶舱 | 按订阅等级解锁不同深度的看板 |

**交付形态**：单店独立部署，按 License 订阅收费
**分期策略**：四个方向同步推进，每期加深功能深度

### 2.2 核心数据流

```
老板付款(第三方发码平台) → 收到激活码 → 填入 AIPet App
  → App 调用 License Server /activate {code, machine_id}
    → Server 验证、绑定机器、签发 License Token
      → App 本地缓存 Token，每 24h 发 /heartbeat
        → 到期前 7 天 App 本地提醒续费
          → 老板再次付款 → 获取续费码 → App 调用 /renew
```

### 2.3 设计原则

| 原则 | 说明 |
|------|------|
| 本地核心不依赖云端 | 触达、内容生成、看板完全本地运行，License 验证有 7 天断网宽容 |
| 云端只管授权 | License Server 只做激活/验证/续费/停用，不碰业务数据 |
| 模板驱动内容 | 内容模板本地打包，可选云端更新，AI 只做模板内变量填充 |
| 分层解锁 | 订阅等级决定功能可用性，不是独立产品，是一套产品的不同深度 |

## 三、License 授权系统设计

### 3.1 激活码格式

```
AIPET-PRO-XXXX-XXXX-XXXX   (Professional 专业版)
AIPET-GRO-XXXX-XXXX-XXXX   (Growth 增长版)
AIPET-STB-XXXX-XXXX-XXXX   (Starter 入门版)
```

16 位字母数字混合，分段便于输入。生成时写入 License Server 数据库（code、plan、status=未激活、过期天数）。

### 3.2 激活流程

```
App 启动
  ├─ 本地有缓存 Token？
  │   ├─ 是 → Token 未过期？→ 正常启动，后台发 /heartbeat
  │   │      └─ Token 过期 → 进入激活页面
  │   └─ 否 → 进入激活页面
  │
  └─ 激活页面（Web / CLI 第一屏）
       输入：激活码 + 门店名称 + 手机号
       POST /activate {code, store_name, phone, machine_id}
         ├─ 200 → 缓存 Token + plan_info → 启动主界面
         ├─ 400 → "激活码无效/已被使用"
         └─ 网络不通 → "请检查网络后重试"（不可绕过）
```

### 3.3 License Server API

| 端点 | 方法 | 功能 |
|------|------|------|
| `/api/activate` | POST | 验证激活码，绑定机器，签发 Token |
| `/api/verify` | POST | App 启动时验证 Token 有效性 |
| `/api/heartbeat` | POST | 每 24h 心跳，更新 last_seen |
| `/api/renew` | POST | 续费码激活，延长有效期 |
| `/api/upgrade` | POST | 套餐升级（入门→专业→增长） |
| `/api/templates/latest` | GET | 拉取最新内容模板（可选，V1.2） |

### 3.4 本地宽容策略

| 场景 | 行为 |
|------|------|
| 正常联网 | 每 24h 心跳，Token 始终有效 |
| 断网 < 7 天 | 使用本地缓存 Token，功能正常运行 |
| 断网 ≥ 7 天 | 弹窗"请连接网络以验证授权"，功能锁定 |
| License 到期 | 提前 7 天每屏提醒，到期后功能降级为 Starter |
| 服务器挂了 | 同断网逻辑，7 天宽容 |

### 3.5 License Server 管理后台

一个简单的 Web 页面（FastAPI + Jinja2），功能：
- 查看所有激活记录（门店、套餐、到期日、最后心跳）
- 手动生成激活码（批量生成 100 个 Pro 码等）
- 停用/恢复某个 License
- 查看到期预警列表（7 天内到期）

### 3.6 对接第三方发码平台

- 首选平台：面包多 / 爱发电（国内个人可申请，API 简单）
- 工作流：用户在平台上付款 → 平台回调 webhook → License Server 自动生成激活码 → 通过平台私信/邮件发送给用户
- 也支持手动模式：你在管理后台批量生成激活码 → 导出 CSV → 手动分发

### 5.2 内容生成流程

```
老板操作：
  选模板（如"朋友圈-洗护前后对比"）
    → 填 3 个关键信息：宠物名 / 品种 / 本次服务亮点

          → 生成配套：话题标签 + AI 绘图提示词（可选）
            → 加入内容日历 → 定时提醒发布
```

- 与上月环比数据

## 十、错误处理与降级策略

| 场景 | 处理方式 |
|------|----------|
| License Server 不可达 | 7 天宽容期，App 使用本地缓存 Token 正常运行 |
| License 过期 | 功能降级为 Starter 入门版（基础提醒 + 手动话术） |
| 企业微信 API 失败 | 自动重试 2 次 → 消息标记 failed → App 提示店员手动处理 |
| LLM API 调用失败 | 降级为模板话术（现有逻辑保持） |
| 内容模板文件损坏 | 回退到内置默认模板，提示重新下载 |
| 触达频率超限 | 自动推迟到下个可用时间窗口 |

## 十二、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 部署形态 | 单店独立部署 | 用户选择，不改为 SaaS 多租户 |
| 收款方式 | 第三方发码平台 | 避免自建支付的合规成本和复杂度 |
| 激活方式 | 在线激活 + 7 天宽容 | 管控能力与离线可用性的平衡 |
| License Server | 独立轻量仓库 | 与主应用分离，独立部署和扩展 |
| 内容生成 | 模板 + AI 填充 | 保证品牌一致性和内容质量 |
| 触达策略 | VIP 人工 + 普通自动 | 兼顾温度感和效率 |
| 看板分层 | 按订阅等级解锁 | 给予升级动力，不增加独立产品复杂度 |
| 项目结构 | 新增 4 个顶层模块 | 与现有 agents/core/services 平级，职责清晰 |
