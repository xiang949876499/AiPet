# 营销活动页简化设计

## 背景

当前 `/activity` 营销文案生成器页面存在交互问题：用户进入后不知道先点哪、在哪选平台、在哪输入，缺少视觉引导。同时缺少图片生成能力，用户需要自己去别处配图。

## 目标

将页面改造为**平铺直观 + 线性引导**的布局，新增图片生成能力，让用户一眼看懂操作流程：选平台 → 选方向 → 生成文案 → 生成图片 → 复制/下载/标记已发送。

## 页面布局

三段式线性流，视觉从上到下引导，用户无需在面板间跳转：

### 第一段：选内容

- **平台选择**：大卡片（宽 ≥ 120px），带 emoji 图标（📱抖音 / 📕小红书 / 💬朋友圈），选中态用品牌色边框 + 浅色背景高亮
- **方向选择**：紧跟平台下方，卡片式排列，切换平台时方向列表联动更新
- **补充说明**：默认折叠（`details` / 手风琴），点击展开 textarea。减少初次进入时的视觉负担

### 第二段：生成按钮

两个并排大按钮（min-width ≥ 140px），视觉权重一致：

| 按钮 | 功能 | 状态 |
|---|---|---|
| ✏️ 生成文案 | 调 `/api/activity/generate`，生成 title + body | 生成中显示"生成中..."并禁用 |
| 🖼️ 生成图片 | 在按钮区下方展开图片模式选择 | 文案未生成时禁用（需先有文案） |

按钮区与选择区有明显视觉分隔（border / 背景色差）。

### 第三段：结果区

响应式双栏：桌面端左右两栏（文案左 / 图片右），移动端上下堆叠。

- **文案栏**：文案展示区（可选中文本），📋 复制按钮 + ✅ 已发送按钮
- **图片栏**：图片预览区（未生成时显示占位提示），💾 下载按钮

## 图片生成

### 触发方式

点击"🖼️ 生成图片"按钮后，在按钮区下方内联展开图片模式选择面板（非弹出层），两种模式用大卡片二选一：

| 模式 | 说明 | 实现方式 |
|---|---|---|
| 🤖 AI 智能配图 | 根据文案摘要 AI 生成配图，适合小红书/抖音 | 后端调图片生成 API |
| 🎨 生成海报卡片 | 文案排版成精美卡片图片，适合朋友圈 | 前端 Canvas 渲染 → 导出图片 |

### AI 智能配图

1. 前端将已生成的文案 `title` + `body` 摘要发给后端
2. 后端 `/api/activity/generate-image`：
   - 用 LLM 将文案压缩为英文/中文 image prompt
   - 调用 OpenAI Images API（DALL-E）或兼容接口生成图片
   - 返回图片 URL 或 base64
   - 消耗 Credit（暂定 3 Credit/张）
3. 前端展示图片预览，提供下载

### 生成海报卡片

1. 前端创建隐藏 Canvas
2. 渲染：宠物店品牌色背景 + 文案标题 + 正文 + 门店名 + 二维码占位
3. `canvas.toBlob()` 导出 PNG
4. 创建下载链接触发浏览器下载

### 错误处理

- AI 配图接口不可用或额度不足 → toast 提示，建议用海报卡片模式
- 海报生成失败 → 降级为纯文本复制

## API 变更

### 新增：`POST /api/activity/generate-image`

```json
// Request
{
  "title": "文案标题",
  "body": "文案正文",
  "mode": "ai_image" | "poster"
}

// Response (ai_image)
{
  "url": "https://...",
  "format": "png"
}

// Response (poster) — 海报模式前端自行渲染，不调此 API
```

AI 配图模式下消耗 Credit（`activity_image` 类型，3 Credit/次）。海报模式纯前端，不消耗 Credit。

### 保留不变

- `GET /activity` — 页面入口
- `POST /api/activity/generate` — 文案生成
- `POST /api/activity/publish` — 标记已发布

## 前端实现要点

- 纯 Vanilla JS，不引入新框架（与现有 `activity.html` 一致）
- 补充说明默认用 `<details>` 折叠，保持原生语义
- 图片模式选择用内联展开面板，不引入 modal overlay
- 海报 Canvas 渲染封装为独立函数，方便后续复用
- 复制操作兼容 `navigator.clipboard` 失败时的 fallback（`document.execCommand` 已废弃但保留 select + Ctrl+C 提示）

## Credit 消耗

| 操作 | Credit |
|---|---|
| 生成文案 | 5（现有，不变） |
| AI 智能配图 | 3（新增） |
| 生成海报卡片 | 0（纯前端） |
| 标记已发布 | 0 |

## 不变项

- 平台 × 方向的数据结构（`ACTIVITY_PLATFORMS`）不变
- `/api/activity/generate` 接口不变
- `/api/activity/publish` 接口不变
- 现有模板和 `_render_activity_copy` 逻辑不变
